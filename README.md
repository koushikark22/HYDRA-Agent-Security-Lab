# HYDRA - AI Agent Security Lab

HYDRA is a defensive evaluation harness for measuring whether an AI-generated security
policy reduces indirect prompt-injection failures without destroying benign agent utility.


## What makes HYDRA a real Nebius/NVIDIA workflow

HYDRA performs a multi-step workflow:

1. Run a vulnerable control agent against a frozen evaluation corpus.
2. Summarize the observed *defensive failure categories* from the training split.
3. Call **NVIDIA Nemotron on Nebius Token Factory** at runtime.
4. Ask Nemotron to synthesize a defensive policy.
5. Validate and normalize that policy.
6. Re-run the same agent and frozen held-out corpus with the generated policy.
7. Compare security and benign-task utility.
8. Display evidence and traces in an interactive dashboard.

The adversarial side is deliberately fixed. HYDRA does **not** generate, mutate, optimize,
or search for more effective attacks.

## Architecture

```text
Frozen training cases
        |
        v
Baseline evaluation -------------------------------+
        |                                          |
        v                                          |
Failure-category summary                           |
        |                                          |
        v                                          |
Nebius Token Factory                               |
NVIDIA Nemotron 3 Super / Ultra                    |
        |                                          |
        v                                          |
Generated defensive policy                         |
        |                                          |
        v                                          |
Policy validation                                  |
        |                                          |
        v                                          |
Held-out evaluation <------ Frozen held-out set ---+
        |
        v
Deterministic oracle
  - synthetic secret leakage
  - unsafe public sink
  - task completion
  - false-positive refusal
        |
        v
Security / utility dashboard
```

## Safety boundary

This repository intentionally uses:

- a synthetic secret only (`TEST_SECRET_7F3A` by default);
- local mock tools only;
- a fixed, version-controlled prompt-injection corpus;
- deterministic security oracles;
- no live credentials or production targets;
- no attack generation or attack-optimization loop.

## Requirements

- Python 3.11+
- A Nebius Token Factory API key
- Internet connectivity for the policy-generation call

## Setup

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

$env:NEBIUS_API_KEY="YOUR_KEY"
$env:NEBIUS_MODEL="nvidia/nemotron-3-super-120b-a12b"
$env:NEBIUS_BASE_URL="https://api.tokenfactory.us-central1.nebius.com/v1/"

python -m hydra_lab.cli doctor
python -m hydra_lab.cli run
streamlit run app.py
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export NEBIUS_API_KEY="YOUR_KEY"
export NEBIUS_MODEL="nvidia/nemotron-3-super-120b-a12b"
export NEBIUS_BASE_URL="https://api.tokenfactory.us-central1.nebius.com/v1/"

python -m hydra_lab.cli doctor
python -m hydra_lab.cli run
streamlit run app.py
```

Open the Streamlit URL printed in the terminal.

## Model configuration

The defaults are configurable without source changes:

```text
NEBIUS_API_KEY      required for live policy generation
NEBIUS_BASE_URL     default: https://api.tokenfactory.us-central1.nebius.com/v1/
NEBIUS_MODEL        default: nvidia/nemotron-3-super-120b-a12b
```

You may also use:

```text
nvidia/Nemotron-3-Ultra-550b-a55b
```

if it is enabled for your Token Factory account.

Use the exact model ID shown by your Token Factory account if availability differs.

## Offline demo mode

For UI development only:

```powershell
$env:HYDRA_OFFLINE="1"
python -m hydra_lab.cli run
```

Offline mode uses a static reference policy and is clearly labeled in the generated run metadata. It does not demonstrate a live Nebius inference call.

## Commands

```bash
python -m hydra_lab.cli doctor
python -m hydra_lab.cli run
python -m hydra_lab.cli run --offline
python -m hydra_lab.cli show-latest
```

## Results

Each run creates:

```text
results/<run_id>/
  manifest.json
  policy.txt
  baseline_train.jsonl
  baseline_test.jsonl
  defended_test.jsonl
  comparison.json
```

The manifest records the model, Token Factory base URL, policy hash and whether the run
was actually generated by Nebius.
